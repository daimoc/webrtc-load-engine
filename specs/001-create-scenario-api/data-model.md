# Data Models for `001-create-scenario-api`

This document defines the data models for the load test scenario feature, based on the `spec.md`.

## 1. Scenario

The core entity representing a load test configuration.

| Field | Type | Description | Validation Rules |
|---|---|---|---|
| `id` | string | Unique identifier for the scenario. | Generated by the system upon creation. Read-only for clients. |
| `name` | string | A user-defined name for the scenario. | Required. |
| `platform` | string | The target WebRTC platform adapter. | Required. Must be one of the supported platform adapters (e.g., "jitsi"). |
| `test_plan` | [TestPlan](#2-testplan) | The object defining the load test parameters. | Required. |
| `status` | string | The current status of the scenario. | Initial status is "created". |

### State Transitions

-   Upon successful creation, the `status` is `created`.

## 2. TestPlan

An object embedded within the Scenario that defines the load parameters.

| Field | Type | Description | Validation Rules |
|---|---|---|---|
| `participants` | integer | The target number of concurrent participants. | Required. Must be an integer greater than 0. |
| `ramp_up_seconds` | integer | The time in seconds over which to add the participants. | Required. Must be a non-negative integer. |
| `duration_seconds`| integer | The duration in seconds the test should run after all participants have joined. | Required. Must be an integer greater than 0. |
